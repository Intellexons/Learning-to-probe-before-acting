\begin{abstract}
\noindent
Outcome-reward RL for LLMs often treats a sampled completion as one trajectory and broadcasts a single scalar advantage to every generated token. For a one-turn completion this is a crude but coherent approximation: the model state evolves by appending tokens to the context. In tool-using or multi-turn agents, the trajectory includes decisions whose effects pass through external state, tool outputs, and later prompts. An early probe or draft is not just a prefix of the final answer; it changes the information available to later turns. Uniformly assigning the final reward to all generated tokens can therefore give the wrong credit signal.

We study this issue in code-policy generation, a minimal setting where the final artifact is executable and objectively scored. The model interacts with a task for two chat turns. In the first turn it may run scratchpad or probe code, or submit a draft policy and observe feedback. In the second turn it must commit a Python \texttt{policy(state)} function. Only this final policy is executed for reward, so useful first-turn behavior receives credit only through its effect on later continuations.

We propose a critic-free estimator that branches rollouts at turn boundaries. For each prompt, the model samples several first-turn variants and several final continuations under each variant. Leaf rewards define a root Monte Carlo baseline for the prompt and a conditional baseline for each first-turn prefix. First-turn tokens are credited when their prefix improves the expected reward of downstream continuations; final-turn tokens are compared only against continuations from the same prefix.

The estimator is paired with a simple implementation for token-summed clipped policy-gradient objectives. Because the objective is additive over disjoint sets of model tokens when all pieces share the same global token normalizer, the loss can be evaluated one turn at a time while accumulating the exact full-trajectory gradient.

We evaluate on a custom slosh-tank control task. The policy observes cart and slosh state but not actuator gain. A first-turn probe can estimate the gain from the response to a commanded pulse; the final policy can then adapt its controller. Frozen two-turn prompting follows the probe format but does not compute or use the gain estimate, leaving a concrete target for RL training.
\end{abstract}

\section{Introduction}

Reinforcement learning is, in part, the problem of assigning credit across decisions. Modern outcome-reward RL for LLMs usually simplifies this problem: sample a completion, score the completed answer, and broadcast a single advantage to all generated tokens. For a one-turn completion this approximation is often serviceable because the dynamics are just autoregressive context growth. Each token influences later tokens by becoming part of the prefix.

That simplification becomes less well matched to tool-using and multi-turn agents. A trajectory may contain natural-language reasoning, tool calls, scratchpad programs, environment probes, candidate solutions, and final answers. These are not merely contiguous pieces of one answer. A tool call can change the external state or reveal information; a scratchpad program can produce observations that later code uses; a draft can shape the next prompt through tool feedback. Treating all generated tokens as equally responsible for the final reward ignores this structure.

This paper studies a small, verifiable instance of that broader problem. The agent must write executable policy code. It is given an environment interface, interacts for two chat turns, and finally emits a Python \texttt{policy(state)} function. The final policy is executed across scenarios and receives a scalar reward. The deployed object is therefore a program, not an LLM queried during control.

This setting connects multi-turn agent RL with recent work on executable discovery. Systems such as FunSearch and AlphaEvolve search over programs using automated evaluation, and AI-Scientist-style systems place code execution inside larger research loops~\cite{romera-paredes2024funsearch,novikov2025alphaevolve,lu2024aiscientist}. Our focus is narrower: rather than building a full discovery system, we isolate one learning problem that such systems face when useful work happens before the final executable artifact is scored.

The key example in this paper is probe-and-adapt control. The environment hides an actuator gain from the policy state. A first-turn program can command a short pulse, observe the velocity change, and infer the gain. A second-turn policy can then rescale its controller. If the final policy succeeds, however, a flat reward does not say whether the first-turn probe was informative or whether the second-turn code happened to work despite it.

We propose a critic-free Monte Carlo estimator for this situation. For each prompt, we sample a small tree: multiple first-turn variants, and multiple second-turn continuations below each variant. The average reward over the whole tree estimates the root value. The average reward below one first-turn branch estimates the value of that prefix. The difference gives a first-turn advantage. The difference between a leaf reward and its prefix value gives a second-turn advantage. Thus, early turns are trained according to the downstream contexts they create, while final turns are trained relative to alternatives from the same context.

This estimator is related to recent multi-turn agent-RL and credit-assignment work. ArCHer learns turn-level values; RAGEN/StarPO studies flat trajectory-level optimization for interactive agents; Agent Lightning frames agent executions as MDP trajectories; and turn-level reward-design methods add intermediate rewards to PPO or GRPO~\cite{zhou2024archer,wang2025ragen,luo2025agentlightning,zeng2025turnlevel}. Our setting keeps the sparse final-reward assumption: no learned value head and no hand-designed turn reward. It also follows the spirit of VinePPO, but branches at tool-turn boundaries rather than inside a single completion~\cite{kazemnejad2024vineppo}.

The implementation uses a standard token-summed clipped surrogate. The useful property is additivity: if all partial losses share the same global token normalizer, the loss can be split across turns. We therefore compute one forward/backward pass per turn and accumulate the exact full-trajectory gradient. This is an implementation device, not the main conceptual contribution.

The contributions are:
\begin{enumerate}
  \item a critic-free turn-level Monte Carlo baseline for sparse-reward multi-turn RL;
  \item an application of this baseline to code-policy generation, where an early turn may gather information used by the final executable policy;
  \item an exact turn-wise implementation of the token-summed clipped objective;
  \item a probe-and-adapt benchmark with a measured blind-vs-oracle gap, plus an ablation design comparing flat multi-turn, branched flat, and hierarchical per-turn baselines.
\end{enumerate}

\section{Related work}

\paragraph{Sparse-reward multi-turn LLM agents.}
Recent work treats LLM agents as sequential decision-makers rather than single completions. ArCHer uses learned turn-level values for language agents~\cite{zhou2024archer}. RAGEN/StarPO studies trajectory-level reinforcement learning for interactive agents~\cite{wang2025ragen}. Agent Lightning casts arbitrary agent executions as MDP trajectories with a credit-assignment module~\cite{luo2025agentlightning}. Other work adds explicit turn-level rewards to multi-turn PPO or GRPO~\cite{zeng2025turnlevel}. These approaches address the same failure mode: a final reward alone is too coarse to say which turn mattered. Our method differs by estimating turn-level baselines from final rewards alone, without a learned critic or manually designed intermediate reward.

\paragraph{Monte Carlo credit assignment without critics.}
GRPO replaces PPO's learned critic with group-relative Monte Carlo baselines~\cite{shao2024deepseekmath}. Token-summed variants such as DAPO modify the normalization for long language-model completions~\cite{yu2025dapo}. These methods are critic-free, but a flat group baseline still assigns the same advantage to every token in a trajectory. VinePPO addresses a related issue by re-branching from intermediate reasoning states and estimating values with Monte Carlo continuations~\cite{kazemnejad2024vineppo}. Our estimator is the turn-level analogue: the branch points are chat/tool boundaries, and the resulting scalar advantage is broadcast to the tokens of the corresponding turn.

\paragraph{Executable discovery and code generation.}
FunSearch, AlphaEvolve, and related systems show that LLMs can search over executable programs using automated evaluators~\cite{romera-paredes2024funsearch,novikov2025alphaevolve}. Work on automatic discovery of RL algorithms broadens this view to machine-designed update rules~\cite{oh2025discorl}. CodeRL, RLTF, and SWE-RL use execution or rule-based feedback to train code generators~\cite{le2022coderl,liu2023rltf,wei2025swerl}. ReVeal is closer to our setting because it uses multi-turn code generation with tool feedback and dense per-turn rewards~\cite{jin2025reveal}. Our setting is different in that the first turn is valuable primarily as information gathering: it may reveal a hidden environment parameter that the final policy should exploit.

\paragraph{Scientific agents.}
AI-Scientist-style systems use LLMs to generate hypotheses, write and run code, analyze results, and draft papers~\cite{lu2024aiscientist}. These systems motivate our setting, but they operate at a higher level of abstraction. We study a smaller trainable component: how to assign credit inside a multi-turn, tool-mediated interaction when only the final executable artifact receives a reward.

\section{Method}

\subsection{Setup}
\label{sec:setup}

The agent is a language model $\pi_\theta$ over chat-template
trajectories. The base is \texttt{Qwen3-4B-Instruct-2507} with
frozen weights $W$; $\theta$ parameterizes a LoRA adapter
$W' = W + AB^\top$. A task $\mathcal{T}$ specifies environment source
code, $S$ scenarios $\{\sigma_i\}$ that vary the seed and hidden
parameters, and a per-scenario reward. The scoring oracle runs a
candidate policy body in a sandboxed subprocess against each scenario
and returns
\(
  R(\text{code};\mathcal{T}) = \sum_i r_i(\text{code};\sigma_i).
\)
Validation failures, errors, and timeouts on $\sigma_i$ score the
\emph{error floor} $r_i = -200$, calibrated below any
running-but-failing trajectory --- otherwise errored rollouts ($r=0$)
outrank running-but-poor rollouts and the gradient rewards crashing.

\subsection{Chat-template protocol}
\label{sec:protocol}

Each turn the model emits one fenced code block tagged \texttt{policy}
or \texttt{main}. \texttt{policy} defines \texttt{def policy(state)},
which the tool executes across all scenarios and reports the summed
reward as a user-role message. \texttt{main} is scratchpad or probe
code run in a rehearsal sandbox; the tool returns truncated stdout but
no final policy reward. The final turn must be \texttt{policy};
\texttt{main} or untagged final turns are floored. Malformed intermediate turns are likewise
floored and surfaced as a textual rejection. A length-$N$ trajectory
is
\(
  \tau = (s,\, y^{(1)},\, m^{(1)},\, \dots,\, y^{(N-1)},\, m^{(N-1)},\, y^{(N)}),
\)
with completions $y^{(n)}$ alternating with tool messages $m^{(n)}$,
and $R(\tau) = R(\text{code in }y^{(N)})$ the only scalar reward.
The remainder of the paper specializes to $N{=}2$: a single
intermediate turn (draft policy or scratchpad) followed by a committed
\texttt{policy}. Generalizing the rollout, advantages, and loss
decomposition below to $N{>}2$ is straightforward (see
\S\ref{sec:limitations}).

\subsection{Token-summed clipped surrogate}

For trajectory $b$ at position $t$, with importance ratio
$\rho^b_t = \pi_\theta / q$ and per-token advantage $A^b_t$,
\begin{equation}
\mathcal{L}(\theta) =
 -\frac{1}{N_{\text{tok}}}\sum_{b,t}
   \mathbf{1}\{\text{model token}\}\cdot
   \min\!\big(\rho^b_t A^b_t,\,\mathrm{clip}(\rho^b_t,\,1-\epsilon_{\text{lo}},\,1+\epsilon_{\text{hi}}) A^b_t\big),
\label{eq:loss}
\end{equation}
with $N_{\text{tok}}$ the count of model tokens in the global batch.\footnote{This
matches the DAPO and CISPO recipes; per-row averaging variants
(original GRPO, BNPO, Dr.GRPO) divide by per-row token counts.}
\eqref{eq:loss} is \emph{additive over disjoint token subsets}: for
any partition of model-token positions, the loss equals the sum of
partial losses computed with the same $N_{\text{tok}}$. This is the
property the per-turn decomposition (\S\ref{sec:per-turn-decomp}) exploits.

\subsection{Branched rollout}

For each prompt $s$, sample $G_1$ turn-1 variants in one
\texttt{model.generate} call:
$y^{(1)}_i \sim q(\cdot\mid s)$, $i=1,\dots,G_1$. For each $y^{(1)}_i$
execute the tool to obtain $m_i$, then sample $G_2$ continuations
$y^{(2)}_{i,j} \sim q(\cdot\mid s, y^{(1)}_i, m_i)$ in one call. Score
each leaf to obtain $\{R_{i,j}\}$. Generate-call cost per prompt is
$1+G_1$, versus $2G_1 G_2$ for an unbranched rollout with the same
number of leaves.

\subsection{Per-turn MC value estimates and advantages}

Two empirical values, both pure averages over the tree:
\begin{equation}
  \widehat V_0 = \frac{1}{G_1 G_2}\sum_{i,j} R_{i,j},
  \qquad
  \widehat V_1^{(i)} = \frac{1}{G_2}\sum_{j} R_{i,j}.
\end{equation}
$\widehat V_0$ estimates the initial-state value;
$\widehat V_1^{(i)}$ the value after committing to turn-1 variant
$y^{(1)}_i$. Per-turn advantages, broadcast to every token of the
corresponding turn:
\begin{align}
  A^{(1)}_{i}      &= \widehat V_1^{(i)} - \widehat V_0
    & \text{(over $y^{(1)}_i$)}, \label{eq:adv1}\\
  A^{(2)}_{i,j}    &= R_{i,j} - \widehat V_1^{(i)}
    & \text{(over $y^{(2)}_{i,j}$).} \label{eq:adv2}
\end{align}
The turn-2 advantage uses the conditional mean given the turn-1
prefix rather than the global per-prompt mean: a poor turn-2 sample
drawn from a strong turn-1 is recognized as poor instead of
inheriting its prefix's above-average outcome. Tool-message tokens
are masked via \texttt{tool\_mask}; their advantage is zero.
Figure~\ref{fig:credit-assignment} contrasts this scheme with the
two closest critic-free / per-turn-credit baselines for multi-turn
LLM RL.

\subsection{Per-turn loss decomposition}
\label{sec:per-turn-decomp}

The token-summed clipped surrogate \eqref{eq:loss} factors over any
partition of the model-token positions into disjoint subsets that
share the same global normalizer $N_{\text{tok}}$. Letting
$\mathcal{I}_n$ index the model tokens of turn $n$,
\begin{equation}
  \mathcal{L} = \sum_{n=1}^{N} \mathcal{L}_{\mathcal{I}_n},
  \qquad N_{\text{tok}} = \sum_{n=1}^{N} |\mathcal{I}_n|.
\label{eq:additive}
\end{equation}
Per-row averaged variants (original GRPO, BNPO, Dr.GRPO) do
\emph{not} factor this way: each row carries its own denominator,
so the partial sums do not combine into the single-row loss. The
token-summed form is what makes the decomposition exact.

\eqref{eq:additive} is exploited to compute $\mathcal{L}$ in $N$
forward/backward passes rather than one. Pass $n$ forwards
$[s \,|\, y^{(1)} \,|\, m^{(1)} \,|\, \dots \,|\, y^{(n)}]$,
computes $\mathcal{L}_{\mathcal{I}_n}$, backwards, and frees. By
\eqref{eq:additive} the parameter gradients accumulated across the
$N$ passes equal the single-pass gradient exactly.

\paragraph{Why this saves memory.} The dominant activation cost is
the LM-head logit tensor ($|V| = 151{,}936$). A single
forward+backward over the full trajectory holds the saved-for-backward
LM-head tensors at all $\sum_n T_n$ model-token positions
simultaneously; doing one forward+backward per turn holds at most
$\max_n T_n$ positions at peak, and \eqref{eq:additive} guarantees
the accumulated gradient is identical. This is gradient accumulation
at the turn level within a trajectory --- the saving is a factor of
roughly $N$ for equal-length turns, $\approx 2\times$ at our $N{=}2$
settings. Appendix~\ref{app:memory} works through the accounting.

\paragraph{Restrictions.} The decomposition's exactness has one
\emph{conceptual} requirement and two \emph{implementation}
requirements. Conceptual: the token-summed normalizer of
\eqref{eq:loss} --- per-row averaged variants do not factor across
token-position partitions, as discussed above. Implementation:
$\beta=0$ (a KL term to $\pi_{\text{ref}}$ would require per-segment
slicing of reference log-probabilities) and
\texttt{num\_iterations}$=1$ (so cached
\texttt{old\_per\_token\_logps} need no re-segmenting). The two
implementation requirements can be lifted with extra bookkeeping at
no theoretical cost (\S\ref{sec:limitations}).

\section{Experimental setup}

\paragraph{Environment.} We use a custom slosh-tank control task rather than a standard benchmark whose solution may already be familiar to the base model. A cart carries liquid represented by a damped pendulum mode. The policy observes
$\{t,x,v,\theta,\omega,g,\text{steps\_left}\}$ and outputs acceleration clipped to $[-1,1]$ m/s$^2$. Success requires reaching the goal while also settling velocity, slosh angle, and slosh velocity. In the V1 task, the only hidden parameter is actuator gain $\kappa\in\{0.65,0.80,1.00\}$; all other parameters are fixed. Full dynamics and the gain sweep are in Appendix~\ref{app:slosh}.

\paragraph{Why it tests turn-level credit.} A first-turn probe can estimate $\kappa$ by commanding a short pulse and measuring $\Delta v/(a_{\rm cmd}\Delta t)$. The final policy can then rescale its controller. This makes the first turn useful only through its effect on the final policy. Blind nominal PD has a large gap to an oracle that divides actions by $\kappa$: at the V1 levels the blind-vs-oracle success gaps are $100$, $49.5$, and $0$ percentage points. Thus the task has one stress level, one transitional level, and one nominal level.

\paragraph{Model and training.} We train LoRA rank $r=16$ on attention projections of \texttt{Qwen3-4B-Instruct-2507}; base weights are frozen, bf16 is used, and gradient checkpointing is enabled. Unless stated otherwise, $G_1=G_2=4$ and each turn is capped at 400 tokens. The loss is the token-summed clipped surrogate \eqref{eq:loss} with $\epsilon_{\rm lo}=0.2$, asymmetric upper clipping, $\beta=0$, no critic, no GAE, and no context truncation across turns.

\paragraph{Diagnostics.} We log $\widehat V_0$, the between-prefix and within-prefix reward standard deviations, their ratio, per-turn advantage scales, error-floor rate, and generate calls per prompt. The between/within ratio is also used diagnostically: values above one indicate that first-turn choice dominates continuation noise, where per-turn credit should help most.

\emph{The format gate fires, the value transfer does not.}
60/60 samples open turn 1 with \texttt{\# MODE: main} and call
\texttt{env.reset()} --- vs.\ 27\% \texttt{main}-mode usage on the
earlier 3B baseline; 21/60 also step the env at least once with a known
commanded acceleration. Yet \textbf{0/60 samples compute a $\kappa$
estimate} from the probe data: the arithmetic that would turn the
printed $\Delta v$ into a gain estimate ---
$\kappa \approx \Delta v / (a_{\text{cmd}}\,\Delta t)$ at
$\theta\!\approx\!\omega\!\approx\!0$ on a single step --- is never
written, even when all of $a_{\text{cmd}}$, $\Delta v$, and $\Delta t$
are on screen. The protocol's intent appears in 60/60 turn-1 comments
(``probing the environment to gain insights about the hidden actuator
gain $\kappa$''); the corresponding code appears zero times.

\emph{Mean reward improves modestly; success rate does not.}
The 2-turn per-sample median mean-reward exceeds the 1-turn median by
12--18 points at every $\kappa$ ($-57.7$ vs.\ $-76.3$ at $\kappa=0.65$;
$-74.2$ vs.\ $-86.8$ at $\kappa=0.80$; $-68.2$ vs.\ $-86.5$ at
$\kappa=1.00$), consistent with the model writing slightly better
controllers in turn~2 after seeing the state shape printed in turn~1 ---
a weak format-side effect, not information gathering. Success rate
stays $\leq 0.7\%$ across all $\kappa$, driven by a single
$\kappa=0.65$ sample whose Pattern-D (reset-only) probe transferred no
information and whose turn-2 body is a clean four-state PD controller
earning $+5.7$ mean reward and 14\% per-seed success rate --- the
first positive frozen-baseline reward on the slosh task, and an
instance of \emph{control reasoning} improving rather than
probe-then-adapt operating.

The probe-then-adapt protocol is therefore \emph{nominal but not
operative}: every sample passes the format gate, the prompt's
instruction to probe is followed, but the value the protocol is
supposed to deliver --- a $\kappa$ estimate that conditions the turn-2
controller --- never materialises. The headline gap RL fine-tuning has
to close is exactly to make $\kappa$-estimation arithmetic appear in
turn-1 probe code and be \emph{read} by the turn-2 policy. The signal
the trainer needs is supplied by the $G_2$ branched continuations of
\S\ref{sec:per-turn-decomp}: a turn-1 probe that contains the
information turn-2 needs should produce, on average, higher-reward
$G_2$ leaves, and the per-turn baseline $\widehat V_1^{(i)}$ of
Figure~\ref{fig:credit-assignment}~(c) is what propagates that signal
back to turn-1 tokens.

\paragraph{Failure modes.} If F does not beat D, the hierarchical baseline is not useful in this domain. If F $\approx$ E while both beat D, the benefit comes from branching rather than turn-level credit. If C--F do not beat A/B, the protocol is better framed as prompting rather than RL training.

\section{Limitations and future work}
\label{sec:limitations}

The implementation and experiments use $N=2$. Extending to more turns is conceptually direct: each boundary value becomes the conditional Monte Carlo mean over the subtree below it, and the loss decomposition applies one partial loss per turn. The cost is bookkeeping and additional forward/backward passes, not a new estimator.

The method also assumes deterministic rewards given the seed. In stochastic environments, the same estimator applies but $G_2$ must grow to separate prefix quality from environment noise. The current implementation uses $\beta=0$ and \texttt{num\_iterations}$=1$; KL penalties and cached old log-probabilities can be supported by storing the same quantities per turn segment.

A natural memory/variance extension is token subsampling within a turn. Since each turn uses one scalar advantage broadcast across its tokens, subsampling tokens is an unbiased estimator of the same token-summed gradient when $N_{\rm tok}$ counts only kept positions. We leave uniform and asymmetric subsampling variants to future work.

\section{Conclusion}

We present a critic-free approach to turn-level credit assignment in sparse-reward multi-turn RL. The method branches rollouts at chat-turn boundaries and uses the resulting Monte Carlo conditional means as per-turn baselines. We apply it to code-policy generation, where the first turn can gather information and the final turn emits the executable policy that receives reward. The token-summed objective also gives an exact turn-wise implementation, but the main goal is credit assignment: giving useful early turns a learning signal when only the final artifact is scored.

\section{Memory accounting and the trailing-window LM-head}
\label{app:memory}

The loss only needs logits whose successor token was emitted by the model; prompt and tool-message logits do not contribute. HF \texttt{transformers} exposes this through \texttt{logits\_to\_keep}: an integer keeps the last $K$ positions, while an index tensor selects arbitrary positions.

This reduces unnecessary logits, but a single forward/backward still holds all selected LM-head outputs until backward completes. With gradient checkpointing, transformer-body activations are comparatively small; the expensive saved tensor is the LM-head output of shape $(B,K,|V|)$. Therefore, a full multi-turn backward over all model tokens scales with $K=\sum_n T_n$.

The per-turn decomposition serializes these positions. Turn $n$ forwards the prefix through $y^{(n)}$, computes the partial token-summed loss for that turn using the global $N_{\rm tok}$, backpropagates, and frees the graph. By additivity of \eqref{eq:loss}, the accumulated gradient equals the single-pass gradient, while the peak LM-head tensor scales with $\max_n T_n$.

\begin{table}[h]
\centering
\small
\begin{tabular}{@{}lll@{}}
\toprule
Regime & Positions through LM head & Logit tensor \\
\midrule
Single pass, no \texttt{logits\_to\_keep} & $T_{\text{full}} = 1350$ & $\approx 13.1$\,GB \\
Single pass, selected model tokens & $\sum_n T_n = 800$ & $\approx 7.8$\,GB \\
Two turn-wise passes & $400$ per pass, freed between & $\approx 3.9$\,GB \\
\bottomrule
\end{tabular}

\end{table}

The decomposition is not a new \texttt{logits\_to\_keep} trick; all regimes use the same primitive. The non-trivial point is that token-summed normalization makes the per-turn gradients sum exactly to the full-trajectory gradient. Per-row-averaged variants would require either a different normalizer or an approximation.

\section{Slosh-tank environment}
\label{app:slosh}

A one-dimensional cart carries liquid represented by one damped pendulum mode. The policy commands horizontal acceleration clipped to $[-1,1]$ m/s$^2$ and observes $\{t,x,v,\theta,\omega,g,\text{steps\_left}\}$. Hidden parameters can include actuator gain $\kappa$, delay $D$, deadband $b$, slosh length $L$, and damping $c$; V1 varies only $\kappa$.

The semi-implicit dynamics use $\Delta t=0.06$ s:
\begin{align}
a_{\rm true} &= \kappa\,\mathrm{deadband}(a_{{\rm cmd}[t-D]}), \notag\\
v &\mathrel{+}= \Delta t\,a_{\rm true}, \qquad x \mathrel{+}= \Delta t\,v, \\
\dot\omega &= -\frac{g}{L}\theta-c\omega-a_{\rm true}, \qquad \dot\theta=\omega. \notag
\end{align}
Success requires $|x-g|<\epsilon_x$, $|v|<\epsilon_v$, $|\theta|<\epsilon_\theta$, and $|\omega|<\epsilon_\omega$ simultaneously, preventing controllers that reach the goal without settling the liquid.

\paragraph{Why actuator gain is the V1 unknown.}
With goal distance $D_g\approx1.8$ m and $a_{\max}=1$ m/s$^2$, the minimum bang-bang transit time is $T_{\rm tr}=2\sqrt{D_g/a_{\max}}=2.68$ s. The episode time gives slack $\tau=T_{\rm ep}/T_{\rm tr}=2.35$. Thus low $\kappa$ does not mainly cause transit failure; it slows near-goal settling because all corrective actions are attenuated. This creates a smooth blind-vs-oracle gap while keeping the probe interpretable: for a short pulse near $\theta\approx\omega\approx0$, $\kappa\approx\Delta v/(a_{\rm cmd}\Delta t)$.
